01
Recap

Where this project started

Last semester

Built the full pipeline for bulk RNA-seq classification from NASA GeneLab / OSDR: preprocessing, feature selection, splits, and baseline neural models over microgravity, radiation, and spaceflight-vs-ground-control conditions.

This summer's question

Can Mixture-of-Experts architectures better model this heterogeneous biological data by letting experts specialize — by species, tissue, or stressor — while sharing a routing network?

Concretely: train separate SLiMPerformer-based experts on human, mouse, and mixed human+mouse ARCHS4 data, then test whether a gate over them beats any single expert on zero-shot NASA OSDR spaceflight evaluation.

02
What we found before this sprint

v1 experts collapsed — and the MoE test was invalid

  • The first 5k human/mouse/mixed experts each trained on per-variant gene vocabularies — meaning gene_embedding[i] referred to a different gene in each expert. Any gate over them was comparing apples to oranges.
  • All three v1 experts also showed gene-mean collapse on OSDR: reconstruction quality (Pearson correlation) sat below the trivial "predict the average expression" baseline.
  • Scaling human-only 5k → 20k samples closed most, but not all, of that gap (OSDR Pearson 0.687 → 0.813, vs. a ~0.85 gene-mean baseline).

03
The fix

v2: one shared gene vocabulary across all experts

Before any MoE routing can mean anything, every expert has to agree on what gene index 4,000 is.

  • Built a canonical gene list — the intersection of protein-coding orthologs, human exon lengths, and mouse exon lengths — so human, mouse, and mixed parquet outputs all share identical column order.
  • Also moved to a deeper architecture (4 layers vs. 2, 30% mask ratio vs. 15%, weight decay 0.01) to give the model more room to escape gene-mean collapse.
  • This sprint: rebuilding the three v2 5k experts (human / mouse / mixed) from scratch on new infrastructure — see next slide — and running the same headroom analysis on data that's actually comparable this time.
04
Infrastructure

Migrated off Savio to a dedicated cloud GPU

The old pipeline lived across a shared team monorepo and Savio's SLURM queue. This sprint: split off a personal repo and stood up a dedicated Jetstream Cloud VM so training isn't queued behind other people's jobs.

  • Jetstream VM — g3.xl: 32 CPU, 117GB RAM, full A100-40GB. Confirmed PyTorch sees the GPU directly.
  • Standalone repo — nasa-rna-moe, split from the team's sp26_nasa monorepo, scoped to just this project's code and data.
  • Persistent volume — 200GB attached, decoupled from the VM's own lifecycle so training checkpoints and data survive instance changes.
  • Reference data rebuilt — ortholog tables, exon-length tables, canonical gene vocabulary, OSDR metadata — all regenerated and version-controlled from scratch.
  • Local↔VM workflow — edit and commit locally, git pull and run on the VM; verified round-trip this sprint.

07
Next steps

What happens after this sprint

  • If headroom justifies it: train the MoE gate (train_moe.py) over the three v2 experts and re-evaluate zero-shot on OSDR.
  • If headroom is still ~noise: treat that as the finding for this update, and investigate whether a deeper/wider architecture (rather than more MoE machinery) is the actual lever — possibly test on the existing human_20k_v2 scale.
  • Either way: expert-specialization analysis — what does each expert actually attend to differently? — is the natural next diagnostic once there's a trained gate to inspect.
  • Infrastructure is now in a state where new experiments don't require waiting on a shared SLURM queue, so iteration speed should be materially faster going forward.
